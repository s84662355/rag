1. 项目目标与边界

核心目标

  • 构建可落地的 RAG 问答系统，支持文档与网页知识接入。
  • 实现完整链路：改写 -> 检索 -> 重排 -> 生成 -> 多轮记忆。
  • 保证知识可维护：支持文档删除、重建索引、Chunk 编辑。

技术边界

  • 后端：Go 原生 net/http（不依赖后端 Web 框架）。
  • 前端：Vue 3 + Vite + vue-router（标准前端框架工程）。
  • 存储：MySQL（结构化元数据）+ Elasticsearch（向量/关键词检索）。

2. 系统架构与数据流

2.1 总体架构

Vue 管理后台
  -> HTTP API (internal/httpapi)
      -> RAG Service (internal/service)
          -> Parser / Chunker / Embedding / LLM / Vector / Store
              -> MySQL (documents/chunks/qa_pairs/kbs)
              -> Elasticsearch (rag index, dense_vector + text)

2.2 两条主流程

入库流程 
上传文件/网页
-> 解析文本
-> 文本切块
-> 写入 chunks 表
-> embedding 向量化
-> 写入 ES 索引
-> document 状态置 ready
问答流程 
用户问题
-> Rewrite（可选）
-> Query Embedding
-> Dense Search + Keyword Search
-> RRF 融合
-> Rerank（可选）
-> QA / Chat 生成答案
-> session 追加历史

4. 数据模型与索引设计

4.1 MySQL 表

表名关键字段说明
knowledge_basesid, name知识库主表，所有数据按 kb_id 隔离。
documentskb_id, raw_text, status原始文档及状态（processing/ready/failed）。
chunksdoc_id, chunk_index, content文档分片内容；唯一键 (doc_id, chunk_index)。
qa_pairsdoc_id, question, answer自动生成 QA 对，关联来源分片。

4.2 Elasticsearch 索引（rag）

  • 字段：chunk_id、doc_id、kb_id、content、content_vector
  • 向量类型：dense_vector（cosine similarity）
  • 当前策略：1 shard / 0 replica（单机环境稳定优先）

5. 配置项说明

server.addr              HTTP 服务地址（默认 :8080）
server.staticDir         静态资源目录（当前 web/dist）
mysql.dsn                MySQL 连接
vector.*                 ES 地址、索引名、向量维度
embedding.*              Ollama embedding 接口与模型
rewrite/rerank/qa/chat   DeepSeek 接口与模型
chunk.maxChars           切块最大字符数
chunk.overlap            相邻块重叠长度

建议将 API Key 从配置文件迁移到环境变量，避免明文入仓。

6. 功能实现方案（逐项）

6.1 文档解析（md/pdf/html/txt）已实现

  • 入口接口：POST /api/documents/upload
  • 实现步骤：按扩展名分流 -> 解析为纯文本 -> 规范化换行/空行。
  • PDF 特殊处理：增加文件头校验与 recover，异常 PDF 返回错误，不再导致服务 panic。
  • 代码落点：internal/parser/parser.go

6.2 网页解析已实现

  • 入口接口：POST /api/documents/url
  • 实现步骤：HTTP 抓取 -> DOM 解析 -> 过滤 script/style -> 汇总正文文本。
  • 输出：标题 + 正文，进入统一入库流水线。

6.3 长文档自动切块（Chunk）已实现

  • 策略：按字符窗口切块，支持重叠；优先在标点/换行处分断，减少语义截断。
  • 参数：chunk.maxChars、chunk.overlap
  • 代码：internal/chunker/chunker.go

6.4 Embedding 向量化已实现

  • 模型：Ollama bge-m3
  • 步骤：每个 chunk 调用 embedding API -> 向量写入 ES 文档。
  • 异常：任一 chunk 失败，文档状态标记 failed 并记录错误。

6.5 多知识库支持已实现

  • 所有文档/分片/检索均带 kb_id，在 SQL 与 ES 侧双重过滤。
  • 支持创建、查询、删除知识库。

6.6 文档检索（RAG 检索层）已实现

  • 入口：POST /api/search
  • 检索对象：chunk，而不是整文档。
  • 返回：命中分片内容、分数、来源类型。

6.7 多路召回（Dense + Keyword）已实现

  • 并发执行向量检索和关键词检索。
  • 使用 RRF（Reciprocal Rank Fusion）融合排序，提升鲁棒性。
  • 调试接口可查看融合前结果：POST /api/retrieve/debug

6.8 问题改写（Rewrite）已实现

  • 在检索前调用 LLM 做语义标准化，优化召回质量。
  • 可通过请求参数 use_rewrite 开关控制。

6.9 重排序（Rerank）已实现

  • 对候选 chunk 做二次相关性排序。
  • 实现方式：LLM 输出 chunk id 顺序，服务端回填排序。
  • 可通过 use_rerank 开关控制。

6.10 QA 自动生成已实现

  • 入口：POST /api/qa/generate
  • 按文档分片逐段生成问答对，写入 qa_pairs。
  • 用于后续训练集准备、FAQ 构建或人工审核。

6.11 多轮对话（Chat）已实现

  • 入口：POST /api/chat
  • 会话维度：session_id；服务端保存最近 N 轮上下文。
  • 回答时注入“检索上下文 + 历史上下文”。

6.12 Chunk 编辑已实现

  • 入口：PUT /api/chunks/{id}
  • 编辑后自动重新 embedding 并覆盖 ES 对应分片文档。
  • 保证“可编辑知识”与“检索索引”一致。

6.13 文档删除已实现

  • 入口：DELETE /api/documents/{id}
  • 先删 ES 索引数据（按 doc_id），再删 MySQL 文档记录。

6.14 文档重建索引已实现

  • 入口：POST /api/documents/{id}/reindex
  • 基于 documents.raw_text 重新切块、重向量化、重建 ES 数据。
  • 重建前会清理旧 chunks 与旧 qa_pairs，避免脏数据。

6.15 服务稳定性保护已实现

  • HTTP 全局 recover，panic 不会打崩整个服务。
  • PDF 解析层独立 recover + 合法性校验。
  • 健康检查接口：GET /api/health。

8. 前端实现方案（Vue）

工程结构

web/
  src/
    App.vue                 左侧菜单 + 顶部栏布局
    router/index.js         页面路由
    composables/useRagConsole.js 共享状态+API调用
    views/*.vue             各功能页
  package.json
  vite.config.js

界面规划

  • 左侧菜单：概览、知识库与文档、分片编辑、检索调试、QA、对话、日志。
  • 右侧内容区：按路由切换页面，所有页面共享同一状态仓（composable）。
  • 重点操作（删文档、重建索引）放在文档列表行内按钮，便于运维。

10. 运维与故障处理

10.1 Elasticsearch 分片不可用（primary shard not active）

  • 典型原因：磁盘水位超限导致分片无法分配。
  • 现有改进：索引副本固定为 0，降低单机分片分配压力。
  • 建议：优先清理磁盘空间；开发环境可临时放宽分配阈值。

10.2 PDF 异常文件导致 panic

  • 现已在解析层和 HTTP 层双重 recover，坏文件只返回错误，不会崩服务。

10.3 状态判定

  • ready：文档入库、向量化、索引完成。
  • failed：流程中断，查看 documents.error_msg 定位原因。
